## 1. 개요

### 1.1 목적
친구들끼리 하는 League of Legends 내전(커스텀 게임)을 관리한다. 참가자를 등록하고, 경기 결과를 기록하고, 쌓인 전적을 바탕으로 실력이 비슷한 두 팀을 나눠 준다.

### 1.2 사용자
| 사용자 | 설명 |
|---|---|
| 운영자 | 내전을 여는 사람. 로그인 없이 등록, 수정, 삭제, 팀 나누기, 경기 기록을 한다. |
| 관리자 | 운영자 본인 (계정 1개). 로그인하면 휴지통에서 삭제한 플레이어와 경기 기록을 되돌릴 수 있다. (2026-11-25 추가) |

### 1.3 범위
| 포함 | 제외 (향후 검토) |
|---|---|
| 플레이어 등록, 조회, 수정, 삭제 | 관리자 외 계정, 회원가입 |
| 경기 결과 기록, 조회, 삭제 | Riot API 연동 (티어, 전적 자동 수집) |
| 플레이어별 전적 (승률, 포지션별 승률, 최근 경기) | 챔피언, KDA 기록 |
| 승률 기반 팀 나누기 (포지션 배치 포함) | 경기 결과 수정 (삭제 후 다시 기록으로 대체) |

### 1.4 용어
| 용어 | 뜻 |
|---|---|
| 플레이어 | 내전에 참가하는 사람. 라이엇 ID로 구분한다. |
| 경기 | 내전 한 판. 블루팀 5명과 레드팀 5명이 뛰고, 한 팀이 이긴다. |
| 참가 기록 | 어떤 플레이어가 어떤 경기에서 어느 팀, 어느 포지션으로 뛰었는지에 대한 기록 |
| 포지션 | TOP, JUNGLE, MID, ADC, SUPPORT |
| 라인별 티어 | 탑·정글·미드·원딜·서폿마다 본인이 생각하는 실력을 티어로 적은 값 (아이언 ~ 챌린저). 마스터 이상은 LP도 적을 수 있다. 팀 나누기에 쓴다 (2026-11-26 추가. 같은 날 솔랭 티어를 없애고 이것만 남겼다) |
| 레이팅 | 내전 보정 승률. 3.3 참고 |
| 전력 점수 | 팀 나누기에 쓰는 플레이어 점수 (라인별 티어 + 레이팅 보정). 3.3 참고 |

## 3. 업무 규칙

### 3.1 플레이어
- 라이엇 ID는 `이름#태그` 형식을 권장하지만 형식을 강제하지는 않는다. 앞뒤 공백은 저장하기 전에 지운다.
- 주 포지션과 부 포지션은 같아도 된다. 부 포지션이 없으면 비워 둔다.

### 3.2 경기
- 한 경기에는 정확히 10개의 참가 기록이 있다. 각 팀에 포지션별로 한 명씩이다.
- 참가 기록의 승패는 저장하지 않고 `참가 팀 == 승리 팀`으로 판단한다.

### 3.3 전력 점수 (팀 나누기용)
- 티어 점수: 아이언 1, 브론즈 2, 실버 3, 골드 4, 플래티넘 5, 에메랄드 6, 다이아몬드 7, 마스터 8, 그랜드마스터 9, 챌린저 10
  - **마스터 이상은 LP를 적으면 8 + LP ÷ 500** (0LP 8점, 500LP 9점, 1000LP 10점, 1500LP 11점). LP를 비우면 위 점수(8, 9, 10)를 쓴다. (2026-11-26 추가)
  - 티어 점수는 맡은 라인의 라인별 티어로 정한다 (아래).
  - 라인별 티어가 없는 옛 플레이어는 그날 참가자들의 주 라인 티어 점수 평균으로 계산한다. 아무도 없으면 골드(4)로 본다.
- 레이팅 = `(승 + 1) / (경기 수 + 2)` (내전 보정 승률)
  - 경기가 없는 신규 플레이어는 0.5(50%)에서 시작한다.
  - 경기 수가 적을 때 1승 0패가 100%로 튀는 것을 막는다.
- **전력 점수 = 티어 점수 + (레이팅 − 0.5) × 4**
  - 내전 성적이 티어를 최대 ±2단계만큼 보정한다는 뜻이다. 내전을 안 했으면 티어 점수 그대로다.
- **포지션 감점** (2026-11-26 추가): 라인별 티어가 없는 사람만, 맡은 포지션이 주 포지션이 아니면 전력을 깎는다. 부 포지션 −1, 그 외 포지션 −2.
  - 라인이 겹쳐서 누군가 다른 라인을 가야 하면 그 팀이 실제로 약해지는 것을 반영한다.
- **라인별 티어** (2026-11-26 추가): 라인별 티어를 다 넣은 사람은 맡은 라인의 티어 점수를 티어 점수로 쓰고, 포지션 감점은 없다.
  - 예: 주 포지션이 미드라도 라인별 티어가 "탑 다이아"면 탑에서 7점, 미드가 "브론즈"면 미드에서 2점. "탑 마스터 750LP"면 탑에서 9.5점.
  - 라인별 티어가 없는 사람(기능 전에 등록)만 참가자 평균 + 포지션 감점으로 계산한다.
- 팀 전력은 팀원 5명이 맡은 포지션 기준 전력(티어 점수 + 내전 보정 − 포지션 감점)의 합이다.

### 3.4 팀 나누기 알고리즘
1. 10명을 5명씩 나누는 모든 경우(126가지)를 계산한다.
2. 경우마다 각 팀 안에서 팀 전력이 가장 높은 배치(120가지 중)를 찾는다. 전력이 같으면 포지션 적합도가 높은 배치를 고른다. 적합도는 주 포지션 2점, 부 포지션 1점, 그 외 0점이다.
   - 라인별 티어가 있는 사람은 잘하는 라인으로, 없는 사람은 주 포지션 → 부 포지션 순으로 간다.
3. 경우마다 불균형 점수를 계산한다: **불균형 = 전력 차이 + 0.5 × 티어 분포 차이**
   - 전력 차이: 두 팀 전력 합의 차이 (포지션 감점 포함). 그래서 라인이 겹치는 사람들은 한 팀에 몰리지 않고 두 팀에 고르게 나뉜다.
   - 티어 분포 차이: 각 팀 티어 점수(라인별 티어가 있으면 맡은 라인의 티어)를 높은 순으로 세워 1등끼리, 2등끼리 … 5등끼리 뺀 차이의 합. 합이 같아도 "다이아 둘 + 아이언 둘" 대 "골드 넷"처럼 구성이 다르면 커진다.
4. 불균형이 **가장 작은 값 + 0.5** 이내인 경우 중에서 두 팀 전력 합이 가장 높은 경우를 고르고, 그것도 같으면 포지션 적합도 합이 가장 높은 경우를 고른다.
   - 실력 균형을 먼저 보고, 비슷하면 다들 잘하는 라인을 맡는 쪽을 택한다는 뜻이다. (2026-11-26: 라인별 티어가 생기면서 "35 대 35"와 "25 대 25"를 똑같이 공평하다고 보던 것을 고쳤다.)
   - 포지션 감점도 실력 차이에 들어가므로, "한 팀만 1명이 부 포지션(-1)"보다 "두 팀 모두 1명씩 다른 라인(-2 대 -2)"처럼 두 팀 감점이 같은 쪽을 먼저 고른다. 다른 라인 가는 사람 수보다 두 팀이 똑같이 손해 보는 것을 우선한다 (2026-11-26 사용자 결정).
5. 블루와 레드는 임의로 정하지 않고, 첫 번째 그룹을 블루로 한다.

### 3.5 랜덤 교체 (라인별로 맞바꾸기)
1. 균형 결과(3.4)에서 같은 포지션끼리 두 사람을 짝짓는다 (라인 매치업 5쌍).
2. 5쌍 각각 바꿀지 말지 정하는 조합 중, 하나도 안 바꾸는 것과 5쌍을 다 바꾸는 것(블루/레드 이름만 뒤집힌 같은 팀)을 뺀 30가지를 만든다. (2026-11-25: 처음에는 1~2쌍만 바꿨으나 사용자 요청으로 5쌍 모두 대상으로 변경)
3. 불균형 점수(3.4)가 원래보다 **2 이하**로 늘어나는 조합만 후보로 남긴다. 후보가 3개보다 적으면 불균형이 작은 순으로 3개를 후보로 쓴다.
4. 후보 중 하나를 무작위로 고른다. 무작위 값(seed)은 주소에 들어가서, 새로고침해도 같은 결과가 나온다.
5. 같은 라인끼리 바꾸므로 모두 자기 포지션은 그대로이고 포지션 적합도도 변하지 않는다.

## 4. 비기능 요구사항
| ID | 요구사항 |
|---|---|
| NFR-01 | 서버가 HTML을 만들어 보낸다 (Spring MVC + Thymeleaf). 별도 프론트엔드 빌드는 없다. |
| NFR-02 | 데이터는 H2 파일 DB(`./data/inhouse`)에 저장해서 서버를 재시작해도 유지한다. |
| NFR-03 | 저장, 수정, 삭제는 POST로 처리하고, 처리 후 redirect해서 새로고침해도 중복 처리되지 않게 한다 (PRG). |
| NFR-04 | 모든 화면 문구와 안내 메시지는 한국어로 한다. |
| NFR-05 | PC 브라우저 기준으로 만들되, 휴대폰 폭(360px)에서도 가로 스크롤 없이 읽을 수 있게 한다. |
| NFR-07 | 저장, 수정, 삭제 요청(POST)은 CSRF 보안 토큰을 검사한다 (스프링 시큐리티). 화면의 폼은 `th:action`이 토큰을 자동으로 넣는다. (2026-11-25 추가) |
| NFR-06 | 서비스 계층 규칙(중복 검사, 경기 검증, 전적 계산, 팀 나누기)은 자동 테스트로 검증한다. |

## 5. 데이터 모델

```
Player 1 ──── N MatchParticipant N ──── 1 Match
```

| 엔티티 | 필드 | 제약 |
|---|---|---|
| Player | id, name, riotId, mainPosition, subPosition, 라인별 티어와 LP(컬럼 top_tier, top_lp, jungle_tier, jungle_lp … support_lp. 자바에서는 `LaneTiers` 하나로 묶음), deletedAt. (예전 솔랭 티어 컬럼 tier는 DB에 남아 있지만 쓰지 않는다) | riotId unique, name/riotId/mainPosition not null (라인별 티어는 예전 데이터 때문에 null 허용). deletedAt이 있으면 삭제된 플레이어 (riotId는 `deleted:{id}:{원래 ID}`로 바꿔 두고, 되돌릴 때 원래대로) |
| Match (테이블 `matches`) | id, playedAt(날짜), winner(BLUE/RED), deletedAt | deletedAt 말고 모두 not null. deletedAt이 있으면 삭제된 경기 |
| MatchParticipant | id, match, player, team(BLUE/RED), position | 모두 not null |
